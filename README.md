# Запись ISCN 2024 и заключение врача-генетика — доклад, отчёт и стенд

Опубликовано: **https://aepavlov-dev.github.io/ISCN-demo/**

Три страницы, работающие как статический сайт, без сервера и без сборки.

| Страница | Что это | Требует сети |
|---|---|---|
| `index.html` | Доклад, 12 слайдов. Листание стрелками, пробелом, Home и End | нет |
| `report.html` | Отчёт: три находки в начале, затем полный текст | нет |
| `stand.html` | Стенд: генерация формул, разбор чужих записей, упражнение | да, при первом открытии |

## Публикация на GitHub Pages

1. Скопировать содержимое этой папки в корень ветки репозитория `ISCN-demo`,
   отдаваемой Pages (`main` с настройкой «/ (root)», либо ветка `gh-pages`).
2. Ничего не собирать: файл `.nojekyll` отключает обработку Jekyll, которая
   иначе может выбросить служебные пути.
3. Открыть https://aepavlov-dev.github.io/ISCN-demo/ — стартовая страница
   `index.html` (доклад), со слайда 12 ведут ссылки на стенд и отчёт.

Все ссылки внутри сайта относительные, поэтому размещение в подпапке
репозитория работает без правок.

## Что нужно стенду от сети

Страница `stand.html` исполняет модуль `iscn_formula.py` прямо в браузере
средой Pyodide. При первом открытии загружается сама среда с
`cdn.jsdelivr.net` — около 10 МБ, 10–20 секунд; дальше браузер берёт её из
своего хранилища. Всё остальное лежит рядом в `assets` и по сети не идёт:
модуль, батарея случаев, таблицы цитобендов, колесо разборщика `lark`.

Никакие данные со стенда никуда не отправляются: вычисление целиком
происходит в браузере.

Номер версии среды закреплён **единственной строкой** в начале
`assets/stand.js`:

```js
const PYODIDE_VERSION = "314.0.6";
```

Отсюда собирается и адрес загрузчика, и адрес самой среды, поэтому разойтись
они не могут. Если среда однажды перестанет загружаться, достаточно заменить
номер в этой строке на действующий из перечня
`https://data.jsdelivr.com/v1/packages/npm/pyodide`.

Если доступа к `cdn.jsdelivr.net` нет, стенд покажет об этом сообщение со
ссылками на слайды и отчёт: они работают без сети.

## Состав папки assets

| Файл | Назначение |
|---|---|
| `iscn_formula.py` | Модуль: формы записи, разборщик, обратная проверка, проверка соглашений |
| `iscn_cases.py` | Батарея случаев |
| `iscn_web.py` | Программный слой стенда: принимает запрос страницы, вызывает модуль |
| `stand.js`, `style.css` | Логика и оформление страниц |
| `cases.json`, `exercise.json` | 45 готовых случаев и 10 случаев упражнения |
| `stats.json` | Все измеренные величины; слайды и отчёт берут числа отсюда |
| `cytoBand_hg38.txt`, `cytoBand_hg19.txt` | Таблицы цитобендов, несжатые |
| `lark-1.3.1-py3-none-any.whl` | Разборщик грамматики |

Таблицы цитобендов лежат несжатым текстом умышленно: GitHub Pages отдаёт
файлы `.gz` с заголовком сжатия, браузер распаковывает их сам, и модуль
получил бы уже распакованные байты там, где ожидает сжатые.

## Как это собрано и как пересобрать

Слайды и отчёт собираются из измеренных величин, а не набираются руками:

```
python build_html.py      # index.html и report.html из assets/stats.json
python -m pytest -q test_iscn_formula.py test_site.py
```

Сборка заканчивается сверкой: каждая числовая величина исходного отчёта должна
найтись в собранной странице. Набор `test_site.py` проверяет, что программный
слой отвечает на все действия, которые запрашивает страница, и что в ответах
есть все читаемые страницей поля — расхождение страницы и модуля иначе
обнаружилось бы только на встрече.

## Порядок проведения встречи

1. Слайды 1–5 — задача и устройство.
2. Слайды 6–9 — цена формы, приёмка, находки в референсных записях.
3. Слайд 10 — наши три образца; со слайда открывается стенд с выбранным
   случаем: `stand.html#case=NA13019-клоны`.
4. Слайд 11 — три отказа; показать вживую на вкладке «Свой случай»: убрать
   механизм и увидеть отклонение кариотипных форм с указанием пункта.
5. Упражнение (вкладка «Упражнение»): десять случаев, каждый пишет формулу
   сам, затем разбор расхождений. Верным считается совпадение с любой
   допустимой формой.

## Что нельзя выкладывать в открытый репозиторий

Репозиторий публичный, поэтому в нём нет и не должно быть:

* **текста ISCN 2024** — книга Karger защищена авторским правом. Предоставленный
  файл и распознанный из него текст остаются во внутреннем хранилище. На слайдах
  и в отчёте приведены только обозначения пунктов и короткие выдержки, необходимые
  для обоснования правила, со ссылкой на издательскую страницу
  https://karger.com/books/book/6011;
* **таблиц результатов по образцам пациентов** — в стенде и на слайдах
  используются три образца линий Coriell с публично известными кариотипами,
  клинических данных нет.

Публикация Chebly и соавторов (Mol Cytogenet 2025;18:16) открытого доступа;
в материалах на неё дана ссылка по DOI, файл не дублируется.

Набор проверок стенда — 31 проверка (`test_site.py`): согласованность действий страницы и
переходника, наличие каждого идентификатора разметки, который ищет сценарий, несжатость
данных, отсутствие запрещённых формулировок во всех профилях, вердикты входного контроля.

Числа на слайдах и в отчёте берутся из `assets/stats.json` и сверяются при сборке:
каждая числовая величина исходного отчёта должна найтись в собранной странице.
